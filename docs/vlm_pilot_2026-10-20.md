# Qwen streetview scoring pilots: October 20, 2026

## Decision and scope

Prioritize **Qwen3.8 Flash for the next evaluation round**, with Qwen3-VL Plus
as the established baseline. Keep Qwen3.7 Plus as an optional comparator and
Qwen3.8 Max for occasional quality checks. This is a candidate-selection
decision from a three-point smoke test, not a validated performance ranking.

The goal is to score pedestrian safety, street interface, greenery/staying
support, and environmental maintenance for the overall scene and each side.
Image selection and scoring are separate tasks: the existing CLIP classifier
selects images; Qwen receives the images and a scoring rubric through a cloud
API. These Qwen pilots do not run the VLM locally.

## What was actually run

Three training points were selected across three randomly chosen road levels,
using seed `20261020`. The same six original 1024 x 512 PNG images were used in
both experiments. The 500-point validation set was not used. This sample was
not balanced across all four road levels and is too small for population claims.

The inputs included the exact extracted text of the private overall/single-side
PDF rubric. The usage PDF was read for workflow context but was not appended to
the model requests. Permitted scores were `0.0, 0.1, 0.2, 0.4, 0.5, 0.6, 0.8,
0.9, 1.0`, or `NA` when the relevant space could not be observed reliably.

Each model made **three independent calls per point**:

| Scope | Images | Scores |
|---|---|---:|
| Overall | Both paired images | 4 |
| Side A | Image 1 only | 4 |
| Side B | Image 2 only | 4 |

No previous scores were included in any request. Overall scores were not
calculated from side scores. A/B follow image order and do not imply physical
left/right. In junction or bridge views, a picture may not identify one target
side clearly; the single-image side protocol itself needs evaluation.

Both rounds used `temperature=0`, `enable_thinking=false`, and JSON object mode.
The explanation fields were explicitly requested answer content, not returned
reasoning traces. Model aliases were used rather than pinned snapshots; prompt
hashes and settings are archived, but exact future output reproduction is not
guaranteed, including at temperature zero.

## Experiment 1: verbose output baseline

`v0` requested scores, a target description, visible evidence, a rubric anchor,
uncertainty, and NA reasons. The output token cap was 2,200.

| Model | Successful calls | Input tokens | Cached input tokens | Output tokens | CNY with observed cache | CNY without cache |
|---|---:|---:|---:|---:|---:|---:|
| qwen3-vl-plus | 9 | 37,224 | 0 | 6,198 | 0.099204 | 0.099204 |
| qwen3.8-max | 9 | 40,776 | 19,200 | 4,844 | 0.462096 | 0.663696 |

The repository audit found that the earlier chat estimate for Max omitted its
reported cached input tokens. CNY 0.663696 was the no-cache estimate; the
cache-adjusted estimate is CNY 0.462096. Connection resets were encountered
and unsuccessful network attempts were retained privately. Those attempts had
no reported usage and cannot be proved free from client logs alone. A temporary
IPv4/official-IP workaround enabled the local run; no fixed IP or proxy settings
are part of the public method.

Max was about 4.7 times more expensive with observed caching, or 6.7 times with
no caching, with no sufficiently large quality evaluation to justify that
premium. Both models produced rule/evidence
inconsistencies. The initial preference for Max as a quality baseline was
therefore provisional rather than an accuracy finding.

## Experiment 2: compact output and three-model comparison

`v1_compact` retained the scoring instructions, rubric, images, and independent
scope protocol, but requested only four scores and one short evidence sentence
per dimension, at most 40 characters. An NA reason occupies the same evidence
field. The output cap was reduced to 900 tokens.

All 27 calls succeeded. Every response passed local checks for allowed scores,
the two expected top-level fields, four evidence fields, and evidence length.
This validates formatting, not factual correctness or rubric compliance.

| Model | Input tokens | Cached input tokens | Output tokens | CNY with observed cache | CNY without cache |
|---|---:|---:|---:|---:|---:|
| qwen3-vl-plus | 37,263 | 0 | 1,482 | 0.052083 | 0.052083 |
| qwen3.8-flash | 40,788 | 26,624 | 1,057 | 0.016848 | 0.035484 |
| qwen3.7-plus | 40,671 | 20,736 | 1,521 | 0.060332 | 0.093510 |

For VL Plus, output tokens fell **76.1%** and calculated total cost fell **47.5%**
relative to v0. Scores also changed. This is one paired trial with a changed
output contract and cap, not evidence that shorter output preserves quality.

The private reference CSV contains prior **AI-assisted annotations**, not an
independently established human gold standard. It was used only after prediction
for descriptive agreement. The same 31 cells with numeric values in all three
models and the reference were used for the following comparison:

| Model | Mean absolute difference from reference, lower is closer | Exact matches / 31 | NA cells / all 36 |
|---|---:|---:|---:|
| qwen3-vl-plus | 0.139 | 10 | 3 |
| qwen3.8-flash | 0.094 | 13 | 0 |
| qwen3.7-plus | 0.168 | 6 | 1 |

There were 36 score cells per model. Four reference cells were NA; one additional
cell was excluded from the common numeric comparison because a model returned
NA. NA disagreements must be reviewed separately. These correlated score cells
are not 31 independent street locations, and this table is **not an accuracy
estimate**. Zero NA is not evidence of better judgments.

Cost = `((input - cached) * input_rate + cached * cached_rate + output * output_rate) / 1e6`.
These are usage-based list-price calculations, not account invoices. They do not
include free quotas, account promotions, or unmetered failed attempts. Future
cache hit rates, output lengths, and prices can differ.

At the same compact-run token volume with **no cache**, scaling to 1,000 points
would be about CNY 17.36 for VL Plus, 11.83 for Flash, and 31.17 for 3.7 Plus.
These are illustrative extrapolations, not production quotes.

Qwen3.7 Flash was considered as an additional low-cost candidate but not called.
Qwen3.5 Plus was not prioritized: an
[October 19 retirement notice](https://www.alibabacloud.com/zh/notice/detail?id=2217)
announced retirement of listed older versions on January 19, 2027. Availability
and account permissions must be checked before adopting any candidate.

## Failure modes worth retaining

- **Invented or unsupported evidence:** VL Plus described a seating area in a
  bridge scene where it was not clearly identifiable. Detailed prose can sound
  confident without being grounded in the image.
- **Anchor mismatch:** 3.7 Plus gave a side greenery score of 0.8 while its short
  evidence described mainly walking space and no seats, without establishing
  the required separate staying support. Earlier Max results also mismatched
  evidence and rubric anchors.
- **Unobserved versus absent:** Flash and 3.7 Plus assigned low pedestrian
  scores where a target-side route was poorly observed. A low number cannot
  automatically replace NA; the visibility judgment must be correct.
- **Dimension leakage:** old-looking facades, parked vehicles, closed shutters,
  and greenery can be counted under the wrong dimension or interpreted too
  strongly. The rubric must control which evidence changes each score.
- **Target-side ambiguity:** bridge and junction views can mix the target road,
  opposite side, and distant branches. Prompt improvements alone may not solve
  image-selection or observation problems.

These are review findings, not exhaustive adjudicated error counts. Scores and
references were not silently edited to improve agreement.

## Output boundaries and next experiment

The final scoring CSV has 21 columns: five identity/image metadata fields,
twelve scores, three notes, and the actual save timestamp. Metadata is filled
by the program. Necessary NA reasons can populate notes. Short evidence,
prompt hashes, model/parameter versions, usage, and review flags belong in a
separate internal record, not extra delivery columns. Model runs must remain
identifiable as model-generated rather than being relabeled as independent
human work.

Next, freeze a larger training-only evaluation subset, separate it from examples
used to design the prompt, and preserve the 500-point validation set for a final
check. Use explicit point/image-duplicate separation and consider spatial
separation. Pin model snapshots where available. Compare scoring error by
dimension and scope, allowed-scale adherence, visible-evidence errors, and NA
agreement. Change one substantive prompt component at a time. Include repeated
runs on a subset to measure output variation.

The current recommendation is to test **3.8 Flash and VL Plus** further, rather
than starting full scoring or spending heavily on Max. A compact-only production
format must pass quality checks; a lower bill alone is insufficient.

## Published versus private artifacts

Published: [versioned instruction fragments](../prompts/qwen_scoring/README.md),
compact JSON Schema, parameter and prompt hashes,
[verbose aggregates](../results/vlm_verbose_pilot_2026-10-20.json),
[compact aggregates](../results/vlm_compact_pilot_2026-10-20.json), a prompt
composer, and an aggregate usage calculator.

Private: original PDFs and extracted rubric text, coordinates, image filenames,
reference annotations, per-point predictions/evidence, API responses and request
IDs, screenshots, the image-embedded HTML reviews, credentials, and machine paths.
The exact original experiment can only be reconstructed with those authorized
private inputs. This commit does not add a production batch-scoring API runner.

The usage calculator runs offline:

```bash
python scripts/summarize_vlm_usage.py /path/to/private/predictions.json \
  --output workspace/vlm/usage_summary.json
```

It reports records without usage rather than assuming they incurred zero charge.
Use a new output path per run; neither helper overwrites an existing output.
